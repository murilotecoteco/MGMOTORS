UC01 – Cadastrar Usuário

Visitante

Objetivo: Permitir que um visitante crie uma conta na plataforma.

Pré‑condições: O visitante não deve possuir cadastro com o mesmo e‑mail.

Fluxo Principal:

  1. O visitante acessa a opção "Criar Conta".
  2. O sistema solicita nome completo, e‑mail, telefone e senha.
  3. O visitante preenche todas as informações.
  4. O sistema valida os dados informados.
  5. O sistema verifica se o e‑mail já está cadastrado.
  6. Caso esteja tudo correto, a conta é criada.
  7. O sistema realiza o login automaticamente.
  8. O usuário é direcionado para sua área pessoal.

Fluxos Alternativos

A1 – E‑mail já cadastrado

  1. O sistema detecta que o e‑mail informado já possui uma conta.
  2. Uma mensagem é exibida informando que o e‑mail já está em uso.
  3. O sistema sugere ao visitante realizar login ou recuperar a senha.
  4. O visitante pode corrigir o e‑mail e tentar novamente, retornando ao passo 3 do fluxo principal.

A2 – Senha não atende aos requisitos

  1. O sistema identifica que a senha não cumpre os critérios mínimos (tamanho, letras/números).
  2. É exibida uma mensagem com os requisitos necessários.
  3. O visitante ajusta a senha informada e reenvia o formulário, retornando ao passo 4.

A3 – Campo obrigatório não preenchido

  1. O sistema identifica o(s) campo(s) vazio(s) ao tentar validar o formulário.
  2. O(s) campo(s) pendente(s) são destacados com mensagem de erro.
  3. O visitante completa as informações faltantes e reenvia o formulário, retornando ao passo 3.

Pós‑condições: A conta é criada e o usuário pode utilizar todas as funcionalidades.

UC02 – Realizar Login

Usuário

Objetivo: Permitir que um usuário acesse sua conta.

Pré‑condições: O usuário deve possuir cadastro.

Fluxo Principal:

  1. O usuário informa e‑mail e senha.
  2. O sistema valida as credenciais.
  3. O sistema inicia a sessão.
  4. O usuário é redirecionado para o painel.

Fluxos Alternativos

A1 – Senha incorreta

  1. O sistema identifica que a senha não confere com o e‑mail informado.
  2. Uma mensagem de "credenciais inválidas" é exibida.
  3. O usuário pode tentar novamente ou selecionar "Esqueci minha senha" (UC03), retornando ao passo 1.
  4. Após múltiplas tentativas incorretas, o sistema pode exigir verificação adicional.

A2 – Conta bloqueada

  1. O sistema detecta que a conta está suspensa ou bloqueada pelo administrador.
  2. É exibida uma mensagem informando o bloqueio e orientando o contato com o suporte.
  3. O login é interrompido até que a conta seja reativada (ver UC13).

A3 – Conta inexistente

  1. O sistema não encontra nenhum cadastro para o e‑mail informado.
  2. É exibida uma mensagem informando que não há conta associada.
  3. O sistema oferece a opção de "Criar Conta" (UC01), retornando ao passo 1.

Pós‑condições: Usuário autenticado.

UC03 – Recuperar Senha

Usuário

Objetivo: Permitir a redefinição da senha.

Fluxo Principal:

  1. O usuário seleciona "Esqueci minha senha".
  2. Informa seu e‑mail.
  3. O sistema envia um link de recuperação.
  4. O usuário acessa o link.
  5. Define uma nova senha.
  6. O sistema salva a nova senha.

Fluxos Alternativos

A1 – E‑mail não cadastrado

  1. O sistema não localiza nenhuma conta com o e‑mail informado.
  2. Uma mensagem genérica é exibida (por segurança, sem confirmar se o e‑mail existe ou não).
  3. O usuário pode conferir o e‑mail digitado e tentar novamente, retornando ao passo 2.

A2 – Link de recuperação expirado ou inválido

  1. O sistema verifica a validade do link ao ser acessado.
  2. Caso expirado, é exibida uma mensagem informando o ocorrido.
  3. O usuário é direcionado a solicitar um novo link, retornando ao passo 1.

A3 – Nova senha não atende aos requisitos

  1. O sistema valida a nova senha informada e identifica que não atende aos critérios mínimos.
  2. É exibida uma mensagem com os requisitos necessários.
  3. O usuário corrige a senha e reenvia, retornando ao passo 5.

Pós‑condições: Senha alterada com sucesso.

UC04 – Pesquisar Veículos

Visitante/Usuário

Objetivo: Permitir localizar veículos anunciados.

Fluxo Principal:

  1. O usuário acessa a página de pesquisa.
  2. Seleciona filtros desejados (marca, modelo, ano, faixa de preço, quilometragem, combustível, câmbio, cor, cidade, estado).
  3. O sistema realiza a busca.
  4. Os veículos compatíveis são exibidos.

Fluxos Alternativos

A1 – Nenhum veículo encontrado

  1. O sistema executa a busca e não retorna resultados compatíveis com os filtros.
  2. É exibida uma mensagem informando que nenhum veículo foi encontrado.
  3. O sistema sugere remover ou ajustar filtros, retornando ao passo 2.

A2 – Erro de conexão com o servidor

  1. O sistema não consegue completar a consulta por falha de rede ou serviço indisponível.
  2. Uma mensagem de erro é exibida com opção de "Tentar novamente".
  3. Ao clicar, o sistema refaz a busca, retornando ao passo 3.

Pós‑condições: Lista de veículos apresentada ao usuário.

UC05 – Visualizar Detalhes do Veículo

Visitante/Usuário

Objetivo: Exibir todas as informações do anúncio.

Fluxo Principal:

  1. O usuário seleciona um anúncio.
  2. O sistema apresenta: fotos, marca, modelo, ano, versão, quilometragem, combustível, câmbio, cor, potência, valor, descrição, cidade, estado e informações do vendedor.

Fluxos Alternativos

A1 – Anúncio removido ou indisponível

  1. O sistema verifica que o anúncio foi excluído, vendido ou pausado pelo vendedor.
  2. É exibida uma mensagem informando que o anúncio não está mais disponível.
  3. O usuário é direcionado de volta à listagem de veículos (UC04), retornando ao passo 1.

A2 – Falha ao carregar imagens

  1. O sistema não consegue exibir uma ou mais fotos do anúncio.
  2. Uma imagem padrão de placeholder é exibida no lugar da foto ausente.
  3. As demais informações do anúncio continuam disponíveis normalmente.

Pós‑condições: Usuário obtém todas as informações do veículo.

UC06 – Favoritar Veículo

Usuário

Objetivo: Salvar anúncios para consulta posterior.

Fluxo Principal:

  1. O usuário acessa um anúncio.
  2. Seleciona "Favoritar".
  3. O sistema salva o anúncio na lista de favoritos.

Fluxos Alternativos

A1 – Usuário não autenticado

  1. O sistema identifica que o visitante não possui sessão ativa.
  2. É exibida uma mensagem convidando a fazer login ou criar conta.
  3. Após autenticar‑se (UC02 ou UC01), o usuário retorna ao anúncio e pode favoritá‑lo, retornando ao passo 2.

A2 – Veículo já favoritado

  1. O sistema identifica que o anúncio já está na lista de favoritos do usuário.
  2. A ação é transformada em "Desfavoritar", removendo o anúncio da lista.

Pós‑condições: Anúncio disponível na área de favoritos.

UC07 – Entrar em Contato com o Vendedor

Usuário

Objetivo: Iniciar negociação.

Fluxo Principal:

  1. O usuário abre um anúncio.
  2. Seleciona "Entrar em Contato".
  3. O sistema apresenta opções de contato (ex.: WhatsApp).
  4. O usuário pode iniciar conversa.

Fluxos Alternativos

A1 – Usuário não autenticado

  1. O sistema identifica que não há sessão ativa.
  2. É solicitado login ou cadastro antes de prosseguir (UC02/UC01).
  3. Após autenticado, o usuário retorna ao anúncio e refaz a ação, retornando ao passo 2.

A2 – Vendedor sem contato cadastrado

  1. O sistema verifica que o vendedor não possui WhatsApp ou meio de contato disponível.
  2. É exibida a opção de enviar mensagem interna pela plataforma (UC-Mensagens) como alternativa.

Pós‑condições: Contato iniciado entre comprador e vendedor.

UC08 – Publicar Anúncio

Vendedor

Objetivo: Cadastrar um veículo para venda.

Pré‑condições: Usuário autenticado.

Fluxo Principal:

  1. O vendedor acessa "Novo Anúncio".
  2. Informa: marca, modelo, ano, versão, quilometragem, combustível, câmbio, cor, valor, descrição, cidade, estado.
  3. Adiciona fotografias.
  4. O sistema valida os dados.
  5. O anúncio é publicado.

Fluxos Alternativos

A1 – Fotos inválidas

  1. O sistema verifica formato, tamanho e quantidade das imagens enviadas.
  2. Caso alguma foto esteja fora dos padrões (formato ou tamanho não suportado), uma mensagem de erro é exibida.
  3. O vendedor substitui ou remove a(s) foto(s) inválida(s) e reenvia, retornando ao passo 3.

A2 – Campos obrigatórios não preenchidos

  1. O sistema identifica campos vazios ao validar o formulário.
  2. Os campos pendentes são destacados com mensagem de erro.
  3. O vendedor completa as informações e reenvia, retornando ao passo 2.

A3 – Anúncio pendente de aprovação

  1. O sistema envia o anúncio para moderação antes de publicá‑lo (UC14).
  2. O vendedor recebe uma notificação informando que o anúncio está em análise.
  3. Após aprovação, o anúncio se torna público; se rejeitado, o vendedor é notificado com o motivo e pode corrigir e reenviar.

Pós‑condições: Veículo disponível para pesquisa.

UC09 – Editar Anúncio

Vendedor

Objetivo: Atualizar informações do anúncio.

Fluxo Principal:

  1. O vendedor acessa seus anúncios.
  2. Seleciona o anúncio.
  3. Altera as informações desejadas.
  4. Salva as alterações.

Fluxos Alternativos

A1 – Dados inválidos

  1. O sistema valida as alterações e identifica inconsistências (ex.: valor negativo, campo vazio).
  2. É exibida uma mensagem apontando o(s) erro(s).
  3. O vendedor corrige as informações e salva novamente, retornando ao passo 3.

A2 – Anúncio já marcado como vendido

  1. O sistema verifica que o anúncio está com status "vendido" e bloqueia a edição.
  2. É exibida uma mensagem informando que anúncios vendidos não podem ser editados.
  3. O vendedor pode reativar o anúncio antes de editá‑lo, se aplicável.

Pós‑condições: Anúncio atualizado.

UC10 – Excluir Anúncio

Vendedor

Objetivo: Remover anúncio da plataforma.

Fluxo Principal:

  1. Seleciona o anúncio.
  2. Escolhe "Excluir".
  3. Confirma a exclusão.
  4. O sistema remove o anúncio.

Fluxos Alternativos

A1 – Vendedor cancela a exclusão

  1. Na etapa de confirmação, o vendedor seleciona "Cancelar".
  2. O sistema mantém o anúncio ativo, sem nenhuma alteração.
  3. O fluxo retorna à tela de "Meus Anúncios" (UC11).

A2 – Anúncio com conversas em andamento

  1. O sistema detecta que há mensagens/negociações vinculadas ao anúncio.
  2. É exibido um aviso informando que os compradores serão notificados sobre a remoção.
  3. Ao confirmar, o sistema notifica os interessados e finaliza a exclusão.

Pós‑condições: Anúncio removido.

UC11 – Gerenciar Meus Anúncios

Vendedor

Objetivo: Permitir acompanhar anúncios publicados.

Funcionalidades: Visualizar anúncios ativos/vendidos; pausar/reativar; editar; excluir; consultar visualizações e contatos recebidos.

Fluxos Alternativos

A1 – Nenhum anúncio cadastrado

  1. O sistema verifica que o vendedor ainda não publicou nenhum veículo.
  2. É exibida uma mensagem convidando a criar o primeiro anúncio (UC08).

UC12 – Denunciar Anúncio

Usuário

Objetivo: Comunicar anúncios irregulares.

Motivos: Informações falsas; fraude; veículo inexistente; conteúdo ofensivo; spam.

Fluxo Principal:

  1. O usuário acessa o anúncio.
  2. Seleciona "Denunciar".
  3. Escolhe o motivo.
  4. Confirma o envio.
  5. O administrador recebe a denúncia.

Fluxos Alternativos

A1 – Motivo não selecionado

  1. O sistema identifica que nenhum motivo foi marcado ao confirmar o envio.
  2. É exibida uma mensagem solicitando a seleção de ao menos um motivo.
  3. O usuário seleciona o motivo e confirma novamente, retornando ao passo 3.

A2 – Denúncia duplicada

  1. O sistema verifica que o mesmo usuário já denunciou este anúncio anteriormente.
  2. É exibida uma mensagem informando que a denúncia já foi registrada e está em análise.

UC13 – Administrar Usuários

Administrador

Objetivo: Gerenciar contas cadastradas.

Funcionalidades: Pesquisar, editar, suspender, excluir e reativar contas.

Fluxos Alternativos

A1 – Usuário não encontrado

  1. O sistema não localiza nenhuma conta com os critérios de busca informados.
  2. É exibida uma mensagem de "nenhum resultado encontrado".
  3. O administrador ajusta os termos e refaz a busca.

A2 – Tentativa de excluir/suspender a própria conta

  1. O sistema identifica que o administrador está tentando agir sobre sua própria conta.
  2. A ação é bloqueada e uma mensagem de restrição é exibida.

UC14 – Moderar Anúncios

Administrador

Objetivo: Garantir a qualidade dos anúncios.

Fluxo Principal:

  1. O administrador acessa anúncios pendentes.
  2. Analisa as informações.
  3. Aprova ou rejeita.
  4. O vendedor recebe uma notificação.

Fluxos Alternativos

A1 – Anúncio rejeitado

  1. O administrador seleciona "Rejeitar" e informa o motivo (ex.: fotos inadequadas, dados incompletos).
  2. O sistema notifica o vendedor com o motivo da rejeição.
  3. O vendedor pode corrigir o anúncio e reenviá‑lo para nova análise (UC09/UC08).

A2 – Conteúdo suspeito ou irregular

  1. O sistema/administrador identifica indícios de fraude ou conteúdo impróprio.
  2. O anúncio é rejeitado e a conta do vendedor é sinalizada para análise (UC13).

UC15 – Gerenciar Categorias

Administrador

Objetivo: Administrar marcas e modelos disponíveis.

Funcionalidades: Cadastrar, editar e excluir marcas e modelos.

Fluxos Alternativos

A1 – Categoria já em uso

  1. O sistema verifica que existem anúncios vinculados à marca/modelo que se deseja excluir.
  2. A exclusão é bloqueada e uma mensagem explica o motivo.
  3. O administrador pode reatribuir os anúncios antes de excluir a categoria.

A2 – Nome duplicado

  1. O sistema identifica que já existe uma categoria com o mesmo nome ao cadastrar/editar.
  2. Uma mensagem de duplicidade é exibida.
  3. O administrador ajusta o nome e salva novamente.

UC16 – Painel Administrativo

Administrador

Objetivo: Permitir a administração completa da plataforma.

Funcionalidades: Dashboard com estatísticas; gerenciar usuários, anúncios, categorias; visualizar denúncias; aprovar/excluir anúncios; gerenciar planos; visualizar relatórios; gerenciar veículos vendidos; monitorar acessos; enviar notificações.

Fluxos Alternativos

A1 – Falha ao carregar dados do painel

  1. O sistema não consegue obter as estatísticas ou listas (erro de conexão/serviço).
  2. É exibida uma mensagem de erro com opção de "Tentar novamente".
  3. Ao clicar, o sistema recarrega os dados do painel.

A2 – Permissão insuficiente

  1. O sistema verifica que o usuário logado não possui privilégios de administrador.
  2. O acesso ao painel é negado e o usuário é redirecionado para sua área comum.

UC17 – Gerenciar Perfil

Usuário

Objetivo: Permitir que o usuário visualize e atualize suas informações pessoais.

Pré‑condições: Usuário autenticado.

Fluxo Principal:

  1. O usuário acessa "Meu Perfil".
  2. O sistema exibe os dados cadastrados.
  3. O usuário altera as informações desejadas.
  4. O sistema valida os dados.
  5. As alterações são salvas.

Fluxos Alternativos

A1 – Campos obrigatórios não preenchidos

  1. O sistema identifica campos essenciais em branco (ex.: nome).
  2. Os campos são destacados com mensagem de erro.
  3. O usuário completa as informações e salva novamente, retornando ao passo 3.

A2 – Dados inválidos

  1. O sistema valida formato de e‑mail, telefone ou outros dados e encontra inconsistências.
  2. Uma mensagem de erro específica é exibida junto ao campo.
  3. O usuário corrige a informação e reenvia, retornando ao passo 4.

Pós‑condições: Perfil atualizado.

UC18 – Alterar Senha

Usuário

Objetivo: Permitir que o usuário altere sua senha de acesso.

Pré‑condições: Usuário autenticado.

Fluxo Principal:

  1. O usuário acessa "Alterar Senha".
  2. Informa a senha atual.
  3. Informa a nova senha.
  4. Confirma a nova senha.
  5. O sistema valida as informações.
  6. A senha é atualizada.

Fluxos Alternativos

A1 – Senha atual incorreta

  1. O sistema verifica a senha atual informada e não confere com a registrada.
  2. Uma mensagem de erro é exibida.
  3. O usuário reinformar a senha atual corretamente, retornando ao passo 2.

A2 – Senhas não coincidem

  1. O sistema compara a nova senha com a confirmação e identifica divergência.
  2. Uma mensagem de erro é exibida.
  3. O usuário reinformar ambos os campos corretamente, retornando ao passo 3.

A3 – Nova senha inválida

  1. O sistema identifica que a nova senha não atende aos requisitos mínimos.
  2. É exibida uma mensagem com os critérios exigidos.
  3. O usuário ajusta a senha e reenvia, retornando ao passo 3.

Pós‑condições: Senha alterada com sucesso.

UC19 – Visualizar Perfil do Vendedor

Visitante/Usuário

Objetivo: Permitir que visitantes e usuários visualizem as informações públicas de um vendedor.

Fluxo Principal:

  1. O usuário acessa um anúncio.
  2. Seleciona o perfil do vendedor.
  3. O sistema exibe: nome, foto, cidade, data de cadastro e veículos anunciados.

Fluxos Alternativos

A1 – Vendedor sem anúncios ativos

  1. O sistema verifica que o vendedor não possui veículos disponíveis no momento.
  2. É exibida uma mensagem informando que não há anúncios ativos no momento.

A2 – Perfil não encontrado

  1. O sistema não localiza o vendedor (conta removida/inexistente).
  2. É exibida uma mensagem de erro e o usuário retorna à listagem de veículos.

Pós‑condições: Perfil do vendedor exibido.

UC20 – Marcar Veículo como Vendido

Vendedor

Objetivo: Permitir que o vendedor informe que um veículo foi vendido.

Pré‑condições: O anúncio deve estar ativo.

Fluxo Principal:

  1. O vendedor acessa "Meus Anúncios".
  2. Seleciona o anúncio.
  3. Clica em "Marcar como Vendido".
  4. O sistema altera o status do anúncio.

Fluxos Alternativos

A1 – Vendedor cancela a ação

  1. Na confirmação, o vendedor seleciona "Cancelar".
  2. O sistema mantém o anúncio com o status atual, sem alterações.

A2 – Anúncio já marcado como vendido

  1. O sistema verifica que o status já é "vendido" e informa ao vendedor.
  2. Nenhuma alteração adicional é realizada.

Pós‑condições: Anúncio marcado como vendido.

UC21 – Receber Notificações

Usuário

Objetivo: Informar o usuário sobre eventos importantes da plataforma.

Fluxo Principal:

  1. O sistema gera uma notificação.
  2. O usuário visualiza a notificação em sua conta.

Tipos: Novo contato; aprovação/rejeição de anúncio; alteração de status; avisos do administrador.

Fluxos Alternativos

A1 – Notificações desativadas pelo usuário

  1. O sistema verifica que o usuário desabilitou este tipo de notificação nas configurações (MG‑CONFIGURAÇÕES).
  2. A notificação é registrada no sistema, mas não é enviada/exibida ativamente.
  3. O usuário pode reativar as notificações a qualquer momento.

Pós‑condições: Usuário informado sobre eventos importantes.

UC22 – Filtrar e Ordenar Veículos

Visitante/Usuário

Objetivo: Permitir que os usuários encontrem veículos de acordo com critérios específicos.

Fluxo Principal:

  1. O usuário acessa a pesquisa.
  2. Seleciona filtros (marca, modelo, ano, faixa de preço, quilometragem, combustível, câmbio, cor, cidade, estado).
  3. Escolhe uma ordenação (menor preço, maior preço, mais recentes, mais antigos).
  4. O sistema atualiza os resultados.

Fluxos Alternativos

A1 – Nenhum resultado após aplicar filtros

  1. O sistema aplica os filtros e a ordenação, mas não retorna nenhum veículo.
  2. É exibida uma mensagem sugerindo remover ou ampliar os filtros.
  3. O usuário ajusta os critérios e o sistema atualiza os resultados novamente, retornando ao passo 2.

Pós‑condições: Lista de veículos filtrada e organizada.

UC23 – Sair da Conta

Usuário

Objetivo: Permitir que o usuário encerre sua sessão.

Fluxo Principal:

  1. O usuário seleciona "Sair".
  2. O sistema encerra a sessão.
  3. O usuário retorna para a página inicial.

Fluxos Alternativos

A1 – Sessão expirada automaticamente

  1. O sistema detecta inatividade prolongada ou expiração do token de sessão.
  2. A sessão é encerrada automaticamente e o usuário é redirecionado para o login.
  3. Uma mensagem informa que a sessão expirou por segurança.

Pós‑condições: Sessão encerrada.

UC24 – Compartilhar Anúncio

Visitante/Usuário

Objetivo: Permitir que um anúncio seja compartilhado.

Fluxo Principal:

  1. O usuário acessa um anúncio.
  2. Seleciona "Compartilhar".
  3. O sistema disponibiliza as opções (WhatsApp, Facebook, copiar link).
  4. O usuário escolhe a plataforma desejada.

Fluxos Alternativos

A1 – Falha ao copiar o link

  1. O sistema tenta copiar o link para a área de transferência e a operação falha (permissão do navegador).
  2. Uma mensagem de erro é exibida com o link visível para cópia manual.

A2 – Aplicativo de destino não instalado

  1. O sistema tenta abrir o aplicativo (ex.: WhatsApp) e este não está disponível no dispositivo.
  2. O sistema redireciona para a versão web da plataforma escolhida como alternativa.

Pós‑condições: Anúncio compartilhado.

UC25 – Enviar Mensagem pelo Formulário de Contato

Visitante/Usuário

Objetivo: Permitir que visitantes e usuários entrem em contato com a equipe da MGMotors.

Fluxo Principal:

  1. O usuário acessa a página "Contato".
  2. Preenche os campos: nome, e‑mail, assunto, mensagem.
  3. Clica em "Enviar".
  4. O sistema valida os dados.
  5. A mensagem é enviada para a equipe responsável.
  6. O sistema informa que a mensagem foi enviada com sucesso.

Fluxos Alternativos

A1 – Campos obrigatórios não preenchidos

  1. O sistema identifica campos vazios ao validar o formulário.
  2. Os campos pendentes são destacados com mensagem de erro.
  3. O usuário completa as informações e reenvia, retornando ao passo 2.

A2 – E‑mail inválido

  1. O sistema valida o formato do e‑mail informado e o identifica como inválido.
  2. Uma mensagem de erro é exibida junto ao campo.
  3. O usuário corrige o e‑mail e reenvia, retornando ao passo 2.

A3 – Erro no envio

  1. O sistema tenta enviar a mensagem e ocorre uma falha (servidor indisponível, sem conexão).
  2. Uma mensagem de erro é exibida com opção de "Tentar novamente".
  3. Ao clicar, o sistema reenvia a mensagem, retornando ao passo 3.

Pós‑condições: Mensagem enviada para a equipe.
